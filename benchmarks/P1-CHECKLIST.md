## 解题与评估隔离

- [ ] 每次建立全新上下文及相同内容的干净 buggy checkout；无 resume/fork、其他组对话、共享记忆、补丁或调查缓存。运行顺序见 manifest；一次只运行一个修复会话，Jev 内部 jobs 为 2。记录无法清除的供应商缓存状态，不能声称“冷缓存”。
- [ ] 使用已具备的容器、独立 OS 身份或同等可验证隔离环境；解题侧仅能读取 bug 证据、复现测试、原有代码及许可工具。评估侧根因、参考补丁、修复后代码、其他组日志和 holdout 不挂载、不经共享进程/路径/网络暴露。保存访问拒绝的核对证据。
- [ ] 从 buggy revision 导出源码并初始化独立仓库，避免完整 Git 历史或远端泄露答案；登记原始 revision 与导出哈希。固定网络策略，禁止获取答案、参考修复或其他组结果。确有历史依赖时另行说明并核实可达对象。
- [ ] **新上下文、Git worktree、`workspace-write` 或 `--ephemeral` 本身都不能证明盲测隔离。** 当前本地环境未验证上述边界；边界不足的运行只能标 `non_blind_rehearsal`，不作为盲测收益证据。
- [ ] 解题代理可以运行复现测试与原有回归；holdout 行为测试只在最终补丁冻结后由评估侧运行。解题时不可见其路径、内容或失败反馈。
- [ ] 评估者在补丁哈希冻结后验证：原复现由失败变通过，独立行为测试与相关回归通过。删除、跳过、放宽测试或改预期以规避 bug 不算成功；允许通过行为验收的不同实现。失败/超时/环境错误原样保留。

## 运行边界与采集

- [ ] A 按复现、局部搜索、最小修复与测试规则正常调查；不调用 Jev，也不强迫构建、填写或展示评分候选 JSON。A 的 `candidate_hash` 可以是 `null`，原因是实验设计不要求候选池。
- [ ] C 使用完整 skill：候选构建、秘密检查、dry-run、一次评分（或按 skill 直接修复/回退）、按完整 `investigation_order` 调查、修复与验证。构建时已读的代码、重复展示、预检与失败等待都计入开销。每个 C run 最多一次评分批次，不自动重试或补跑。
- [ ] 单批：最多 12 候选、每段 2 KiB/60 行、JSONL 总载荷 24 KiB、jobs 2、socket 10 秒、整批 45 秒、outer retries 0。版本预检限 2 秒、stdout+stderr 合计 1024 字节，预检与评分期限合计最多 47 秒，启动等实际开销仍计入总时长。全局最多 12 次主模型修复、6 个 C 评分批次、72 个逻辑评分、144 次 HTTP 尝试上界；预检最多 6 次，以 `cli_preflight.invocations` 单独计数并计时，`usage.cli_invocations` 仍只指评分进程。预检/评分失败也消耗已发生的预算。
- [ ] HTTP 上界只适用于已核对的 Jev 0.3.2；未知版本或预检失败回退并禁止评分。上界不是实际 HTTP 次数、成功数或费用；不为获取 usage 额外重发评分。
- [ ] 从收到任务到最终验证结束计时，分开记录收集、预检/评分、调查、修改和测试；保留事件时间、退出码、失败分类、ranker JSON、补丁和验证日志。评估工具开发、样本准备与答案标注另列。

## 全局停止条件

在每次启动前及运行中检查累计 ledger。任一项触发即停止当前有关进程及后续启动，保存记录；已经发生的失败与费用不丢弃：

1. 时间/费用上限已到，或剩余预算不足以预留下一 run 的上限；没有可执行的费用限额或监控手段时禁止启动。
2. 超过 12 主模型修复、6 C 批次、72 逻辑评分、144 HTTP 上界、6 预检，或任何单批限制。额外重跑/重复仍须累计，首轮总额不自动增加。
3. 隔离泄露、源码/秘密审查未完成、模型/推理/环境漂移、关键记录丢失或未登记的协议变更。数据保留并标偏离，不暗中补跑。
4. C 出现同题 A 未出现的修复失败，暂停后续 C 运行和扩样，先定位；尚未运行的配对如实标未完成。环境失败与产品失败分别记录，不排除失败样本。
